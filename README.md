# 孙本位 / sun-standard

先把一段经历审计成一张账本，再写成文章。

不许编数字。

---

## 为什么先记账

那篇文章从不说"我难过"。它说那面朝着大西洋的玻璃要整块换掉。

从不说"她铺张"。它说 A330 按两百人设计，只坐三十个，太轻，配平不对，
所以每次都多加油加到够重，到了地方再放掉。每次都这样。

情绪全部由会计科目承载。作者只负责报数。

所以这个 skill 不教文风。让模型模仿文风一定滑坡——它天生想加形容词、想解释情绪、
想在结尾升华。但如果强制先走一遍审计，交到写作环节手里的只剩数字和动作，
它就没有材料可以抒情。

**账本是风格的护栏。**

---

## 它产出三样东西

**一，正文。**

**二，结账单。** 文章长没人转，这个才是传播物。

```
结账。一次爆仓。

咖啡二十二块。那天没买。
仓位十八万美元。加了第三次。
加仓三次。第三次没有想。
还有行情软件，一千零五十六块，年费，还剩十一个月。
还有手续费，两千一百四十美元，赚赔都要付。
还有止损单，一张，设了，改了，删了。
强平三点四十七分。系统消息，四个字。
静音六个小时。十四个未接。
心跳八十八下。比平时快一点。

第二天照常开盘。
```

同时出一份 SVG，深底，可以直接截图当配图。

**三，跑分。** 零到一百，纯计算，没有 LLM 打分。

---

## 跑分抓什么

六个维度。账本密度、句子长短、克制动作、抒情词、损耗科目、结尾升华。

抒情滑坡是这套文体最常见的复发。跑一段试试：

```
前台把工牌收走了。
我在门口站了一会儿。
那一刻，我终于明白了。
三年的青春就这样落幕。
```

结果：

```
账本密度 62.7 / 100。

计量点一个，四十二点五字。每百字二点三五个，目标两点四。二十五分里拿到二十四点四。
四句，平均一句九点二字。目标十六以内。二十分，拿满。
一处克制动作也没有。嘴一直在说话。二十分，扣光。
抒情词零处。干净。十五分，拿满。
没有一项花了什么也没换来的东西。最疼的地方缺了。十分，扣光。
结尾升华「终于明白」。十分里拿到三点三。

半途而废：数字有了，嘴还在说话。
```

分数低于八十五不交付。按扣分项改一轮再跑。

已校准：原文级样本一百分，同一个故事的抒情滑坡版三点六分。

## 审计五问

用户给完材料，先不写。先问缺的东西。

一，**锚点物**。这件事里最便宜、但你真的犹豫过的那个东西是什么？多少钱？犹豫了多久？
原文是一件一百五十块的羽绒服，犹豫三天。没有锚点物，全文没有支点。

二，**真正的数**。你没有犹豫的那个大数是多少？

三，**损耗项**。花了钱，或者花了功，最后什么也没换来的是哪几项？
不退的定金、没拆的针、放掉的燃油。这是全文最疼的地方。

四，**隐形劳动者**。谁为这件事做了没人看见的活？他的工序是什么？
不是他的心情，是他怎么干的。

五，**身体计量**。那个瞬间的可测数据。沉默几秒，心跳几下，几个未接，几点几分。

答不出的留空。**绝不替他填。**

## 用

```bash
cd ~/.kiro/skills/sun-standard

python3 run.py score 正文.md              # 跑分，也吃 stdin
python3 run.py card ledger.json           # 结账单，出 txt + svg
python3 run.py compare compare.json       # 对照图，出 svg
python3 run.py convert 4800               # 换算成孙本位
python3 run.py rates                      # 看汇率表
```

纯标准库。不联网。不要任何 key。任何子命令加 `--json` 出机器可读。

对照是这套文体的第二号招式，三点五微克放在两点五吨旁边，不替任何一方发言。
`compare` 把它渲成图：上栏压暗，下栏提亮，中间不写一句评语。

## 孙本位汇率表

```
$ python3 run.py convert 50000000 -c USD

五千万美元。

五十层空楼。一层一百万美元，三十天，住了八天。
十一点八份彩礼。一份三千万元，两个名字，两个账号。
八点零六根香蕉。一根六百二十万美元，会烂。
二点三七部大片。一部一亿五千万元，请来做陪衬，什么都没有发生。
一通电话。一通五千万美元，让我想想。
零点三三三部合拍片。一部一亿五千万美元，名单越来越长。
```

小额用不上汇率表。九块九换出来是零点零六六件羽绒服，没劲。
小额的支点是事情内部的自换算：走了一千米，喝了两口，五百米一口。

单位分六类。钱、重量、人头、时长、计数、损耗。数字全部取自作者本人公开发布的文本里
他自己写出来的数。改 `rates.json` 可以加自己的单位。

## 里面有什么

```
sun-standard/
├── SKILL.md              审计流程 + 十四条招式 + 禁则
├── sun_standard.py        引擎：换算 / 跑分 / 结账单与对照图渲染
├── run.py                 命令行
├── rates.json             孙本位汇率表
├── ledger.example.json    账本模板
└── examples/
    ├── liquidation.*        一次爆仓，一百分
    ├── resume.*             一份简历，一百分
    ├── resume.compare.json  同一份简历的对照图
    ├── luckin.*             一杯瑞幸，九十五分
    └── anti-pattern.md      抒情滑坡版，三点六分
```

中文数字是代码转的，不是模型写的。一千零五十六。两千一百四十。两口，不是二口。
九块九。四块九毛五。

## 禁则

一，**绝不编数字。** 所有数字必须来自用户给的事实。缺了就问，问不到就留空。
这套文体全靠数字的可核验性支撑，编一个就全毁了。

二，**不针对真人。** 这是文体项目，不是人身攻击工具。不生成针对任何具体真人的指控、
羞辱或私密推测。用户写的是自己的经历。涉及他人时只写可观察的行为和数字，不写动机揣测。

三，**结尾不许升华。** 不和解，不感恩，不"我终于明白"，不"未来还很长"。

四，**不解释情绪。** 情绪只能被计量，不能被描述。

五，**不排表。** 结账单、跑分、汇率换算，全部报数成句。不用对齐列，不用竖线，
不用进度条，不用 markdown 表格。表格一出来，文体就死了。

## 相关项目

[KKKKhazix/sun-style-writing](https://github.com/KKKKhazix/sun-style-writing) 比这个早，
把原文拆成了十种叙事手法，是一份写得很好的心法。

两个项目切的是不同的面：他蒸馏文法，这个做记账引擎。
他那份是提示词，靠模型自觉；这份强制先落结构化账本再动笔，并且用代码把复发检测出来。
他在 README 里说模型有时会写出"那一刻，我终于明白了"，欢迎提 Issue。
这份的跑分器会直接把那句判出来扣分。

两个一起装不冲突。
